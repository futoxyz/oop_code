# ЛР5. Дерево книг и умные указатели

**Вариант 4.** У книги есть название, автор, год и число страниц. Ключ дерева —
год. Отбор по варианту: `lo <= year < hi && pages >= minPages`.

| Файлы | Что в них |
| --- | --- |
| `book.h` и `book.cpp` | `Book` и критерии отбора книг |
| `book_tree.h` и `book_tree.cpp` | `BookTree`, его узел и массив результата `Selection` |
| `main.cpp` | Пример на шести книгах |
| `tests.cpp` | Проверки Google Test |
| `CMakeLists.txt` | Сборка `main` и `tests` |

## От обычного BST к этому коду

Начни с `main.cpp`. Он вставляет книги, печатает их по году и сохраняет результат
отбора. После удаления книги 1965 года та же выборка печатается ещё раз. В ней всё
ещё три места, но вместо первой книги теперь `[expired]`.

| Тип | Что хранит и за что отвечает |
| --- | --- |
| `Book` | Две строки и два целых числа. `<` и `==` сравнивают только год. Поэтому второй книге того же года вставка откажет. `Book(1965)` создаёт эталон ключа с пустыми строками и нулём страниц. |
| `BookTree::Node` | `unique_ptr<Node>` на каждого ребёнка, `shared_ptr<Book>` на книгу. |
| `BookTree` | `unique_ptr<Node>` на корень и текущий размер. Вставляет, ищет и удаляет книги, считает высоту, обходит дерево. |
| `Criterion` | Интерфейс с виртуальным деструктором и методом `matches(const Book&) const`. `BookSelector` хранит границы и порог, `AllBooks` принимает любую книгу. |
| `Selection` | Размер, вместимость и `unique_ptr<weak_ptr<const Book>[]>` на массив результата. |

Год должен быть положительным, число страниц — неотрицательным. Строки
сохраняются как есть. Копирующий конструктор книги нужен для вставки. Дерево
создаёт свою книгу через `make_shared`, и она продолжает жить после уничтожения
аргумента `insert`. Перемещающий конструктор переносит строки самостоятельной
книги. Каждый созданный объект, включая эталон и результат перемещения,
учитывается в `Book::liveCount()` до своего уничтожения. Присваивание книг
запрещено, чтобы год записи оставался постоянным.

### Вставка и удаление

`findLink` возвращает ссылку на `unique_ptr`, в котором найден узел или куда его
нужно вставить. В коде BST на C это похоже на получение `Node**` для изменения
`root`, `left` или `right`. Здесь присваивание через эту ссылку передаёт владение
узлом. Для обычного чтения `find` спускается по дереву через `.get()` и возвращает
слабую ссылку на книгу, если ключ нашёлся.

- У листа место узла становится пустым. Если есть один ребёнок, его указатель
  переезжает на место узла. Локальный `removed` держит старый узел живым, пока
  из него забирается дочерний указатель.
- Если детей два, берём крайний левый узел справа. Переносим его `shared_ptr` с
  книгой в узел, который удаляем, а на место преемника переносим его правого
  ребёнка. Это сохраняет сам объект книги-преемника и все слабые ссылки на него.

Вставка, поиск и удаление занимают `O(h)`, где `h` — высота дерева. Высота
пустого дерева равна 0, листа — 1. `height()` обходит все узлы, а `size()`
возвращает сохранённое число. Дерево не балансируется.

Определение `Node` находится в `book_tree.cpp`, а в заголовке есть только
`struct Node;`. Там же, где видны поля узла, определены конструкторы,
деструктор и перемещающее присваивание дерева. При освобождении
`unique_ptr<Node>` компилятору нужен полный тип узла. Копирование дерева
запрещено. Перемещение забирает корень и размер и обнуляет размер источника.
При разрушении дерева корень освобождает детей, те — своих детей.

### Как работает отбор

`BookTree::select(const Criterion&) const` один раз обходит дерево слева направо.
В каждом узле он вызывает `matches` и сразу добавляет слабую ссылку, если ответ
`true`. Книги идут по возрастанию года благодаря порядку обхода. Время `O(n)`,
стек рекурсии `O(h)`, массив результата занимает `O(k)` для `k` совпадений.
`inOrder()` использует тот же обход без фильтра, `reverseOrder()` меняет порядок
посещения поддеревьев.

`Criterion` играет ту же роль, что базовый `Shape` в ЛР4. Дерево вызывает
виртуальный метод, а конкретный класс решает, подходит ли книга. В `BookSelector`
две короткие проверки удобно держать в одном `matches`. Второй критерий,
`AllBooks`, нужен для проверки, что `select` принимает и другой класс.
Нижняя граница года положительна, верхняя может быть равна нижней, порог
страниц неотрицателен. Равные границы дают пустой интервал.
У критериев только обычные поля, поэтому специальные реализации копирования
и перемещения им не нужны. `select` пользуется критерием по ссылке.

### Что лежит в выборке

`Selection` устроен как массив из ЛР3. Если места мало, `append` выделяет
буфер с удвоенной вместимостью, копирует туда слабые ссылки и добавляет элемент.
Первая вставка выделяет 1 место. Добавление занимает амортизированно `O(1)`.
Если совпадений нет, результат пустой и буфер не выделяется. Выход за границы
при доступе по индексу даёт `std::out_of_range`.

- При копировании выделяется отдельный массив и копируются слабые ссылки.
  Копирующее присваивание сперва создаёт временную копию, затем меняет с ней
  буфер, размер и вместимость. При ошибке выделения прежняя выборка сохраняется.
- При перемещении массив переезжает целиком. Размер и вместимость источника
  обнуляются, и его можно снова заполнять. При уничтожении массива `unique_ptr`
  освобождает буфер автоматически.

`weak_ptr` наблюдает за книгой через служебный блок `shared_ptr`. Из
`unique_ptr` получить такую ссылку нельзя. Когда последний `shared_ptr` на
книгу исчезает, все её слабые ссылки истекают. Чтобы прочитать книгу, вызови
`lock()` и проверь результат. Успешный `lock()` сам создаёт временный
`shared_ptr`. Пока он хранится, книга переживёт даже удаление из дерева.

## Тесты

В ЛР5 29 тестов на обычных `TEST`, как в предыдущих лабах. `ASSERT_*` прерывает
текущую функцию при провале проверки. Например, в `expectYears` после
`ASSERT_TRUE(book)` безопасно читать `book->year()`. `EXPECT_*` отмечает ошибку
и продолжает остальные проверки. Объявления `static_assert` в начале файла
проверяют свойства классов на этапе компиляции.

Для разбора начни с `BookTree.removes_root_with_two_children`. Тест проверяет
порядок после удаления, а также что старая ссылка истекла и книга-преемник
сохранила свой адрес. Затем посмотри `Selection.copy_has_own_array_and_both_refs_expire`,
где у двух выборок разные массивы, но одинаковые наблюдаемые книги.
`Lifetime.removal_and_destruction_release_records` проверяет счётчик после
удаления и в конце жизни дерева. Соседний тест показывает, что меняется, если
сохранить результат `lock()`.

## Сборка

Из папки `lab5`. Нужны CMake 3.20+, C++20 и Git для первого скачивания Google Test.

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
.\build\main.exe
```

Если используешь Ninja с MinGW и папка сборки новая, добавь `-G Ninja` к первой
команде. Для Visual Studio добавь `--config Debug` к сборке и `-C Debug` к
`ctest`. Приложение будет в `build/Debug/main.exe`.

В CMake две цели с общими исходниками. `FetchContent` получает Google Test,
`GTest::gtest_main` предоставляет точку входа для `tests`, а
`gtest_discover_tests` делает каждый `TEST` видимым в CTest.
Если Google Test уже скачан в корневой `build/_deps/googletest-src`, к первой
команде можно добавить `"-DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=$((Resolve-Path ../build/_deps/googletest-src).Path)"`.

Обычная сборка включает предупреждения. Для обязательного прогона ASan/LSan
на Linux с GCC или Clang используй отдельную папку сборки:

```bash
cmake -S . -B build/asan -DCMAKE_BUILD_TYPE=Debug -DENABLE_ASAN=ON
cmake --build build/asan
ASAN_OPTIONS=detect_leaks=1 ctest --test-dir build/asan --output-on-failure
ASAN_OPTIONS=detect_leaks=1 ./build/asan/main
```

В установленном MinGW обычная сборка и 29 тестов прошли. Линковка с
`ENABLE_ASAN=ON` остановилась на `cannot find -lasan`, поэтому прогон
ASan/LSan в этой среде пока не выполнен.
