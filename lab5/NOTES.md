# ЛР5. Разбор дерева книг

Это конспект к [README.md](README.md). Начни с демонстрации в [main.cpp](main.cpp),
затем найди объявления в [book_tree.h](book_tree.h) и пройди по реализации в
[book_tree.cpp](book_tree.cpp). Запись книги и критерии находятся в
[book.h](book.h) и [book.cpp](book.cpp).

## Что делает программа

Вариант 4 хранит книги с названием, автором, годом и числом страниц. Ключ —
**год**. Слева от узла лежат меньшие годы, справа — большие. Вторая книга
того же года считается дубликатом. Критерий варианта отбирает книги по условию
`lo <= year && year < hi && pages >= minPages`. [Условие ЛР5](../tasks/lab_05_smart_pointers_2026-11-14.pdf)

В `main.cpp` дерево заполняется шестью книгами, затем печатается по возрастанию
года. Выборка по интервалу `[1960, 1990)` и порогу `250` даёт три книги.

```text
3
Dune Herbert 1965 412
TheDispossessed LeGuin 1974 341
Neuromancer Gibson 1984 271
```

После `tree.remove(Book(1965))` печатается та же выборка. Размер по-прежнему
равен трём, а в первой строке данных теперь `[expired]`.

## Как читать объявления

| Запись | Что она означает здесь |
| --- | --- |
| `const Book& book` | Ссылка на книгу для чтения. Вызов функции сам по себе книгу не копирует. Сюда можно передать временный `Book(1965)`. |
| `std::size_t` | Беззнаковый целочисленный тип для размеров и индексов. |
| `height() const` | Метод можно вызвать у константного дерева. Последний `const` относится к дереву, на котором вызван метод. |
| `noexcept` | Метод обещает, что исключение из него не выйдет. Вставка и выборка могут выделять память, поэтому такого обещания у них нет. |
| `static` | У метода нет объекта `this`. Например, `Book::liveCount()` вызывается через имя класса. |
| `= default` | Компилятор генерирует обычную реализацию специального метода. |
| `= delete` | Использовать эту операцию нельзя. Так запрещено копирование дерева. |
| `T&&` | Rvalue-ссылка. В конструкторах перемещения и соответствующих присваиваниях она позволяет передать объект, из которого можно забрать ресурсы. |

`std::move(x)` позволяет выбрать перемещающий конструктор или присваивание.
Владение фактически меняется внутри выбранной операции. Например, после
`newOwner = std::move(oldOwner)` у `unique_ptr` старый владелец пуст.

## Book и сравнение по ключу

| Метод | Аргументы и результат |
| --- | --- |
| `Book(title, author, year, pages)` | Принимает две `std::string` и два `int`. Создаёт книгу. Год должен быть положительным, число страниц — неотрицательным. При неверных данных бросает `std::invalid_argument`. |
| `explicit Book(int year)` | Создаёт эталон с указанным годом, пустыми строками и нулём страниц. |
| `Book(const Book& other)` | Создаёт самостоятельную копию полей книги. Дерево использует этот конструктор при вставке. |
| `Book(Book&& other)` | Перемещает строки в новую книгу и копирует числовые поля. Исходный объект остаётся жив. |
| `~Book()` | Уменьшает счётчик живых книг. У конструктора и деструктора нет возвращаемого типа. |
| `title()`, `author()` | Возвращают `const std::string&` на соответствующее поле. |
| `year()`, `pages()` | Возвращают `int` по значению. |
| `liveCount()` | Возвращает `std::size_t`. Считает все живые объекты `Book`. |

`explicit` запрещает неявное превращение числа в книгу. Вызов
`tree.find(Book(1965))` показывает, что создаётся эталон. Вызов
`tree.find(1965)` не скомпилируется. Два присваивания `Book` запрещены, чтобы
ключ существующей записи оставался постоянным.

`Book::liveCount_` — одно статическое поле на весь класс. Успешный конструктор
увеличивает счётчик, деструктор уменьшает. Если вставить локальную книгу
`Book book(1965)` в пустое дерево, `tree.size()` будет равен `1`, а
`Book::liveCount()` — `2`. Один объект находится у тебя, второй — внутри узла.
Копия `shared_ptr` удерживает ту же книгу, поэтому сам счётчик объектов при
копировании указателя не увеличивается.

В `Book` два явно написанных оператора сравнения.

- `operator==` принимает `const Book&`, возвращает `bool` и сравнивает годы.
  Через него компилятор обрабатывает `!=`.
- `operator<=>` тоже принимает `const Book&`. Возвращает
  `std::strong_ordering` из `<compare>` со значением «меньше», «равно» или
  «больше». На его основе работают `<`, `<=`, `>` и `>=`. Например, выражение
  `a < b` проверяется как `(a <=> b) < 0`.

Явное тело `return year_ <=> other.year_;` оставляет в сравнении только год.
Оператор с `= default` сравнивал бы и остальные нестатические поля.

## Узел и владение памятью

`BookTree` хранит `root_` и `size_`. Его вложенный `Node` содержит книгу и два
дочерних указателя. `Node(const Book& value)` создаёт копию книги через
`std::make_shared<Book>(value)`. Дочерние указатели изначально пустые.

| Тип | Роль в ЛР5 |
| --- | --- |
| `std::unique_ptr<Node>` | Единственный владелец узла. Корнем владеет дерево, остальными узлами — их родители. |
| `std::shared_ptr<Book>` | Сильный владелец книги в узле. Через его служебный блок `weak_ptr` может узнать, жива ли книга. |
| `std::weak_ptr<const Book>` | Наблюдает за книгой и сам её не удерживает. Такой указатель отдаёт `find()`. Такие же указатели хранятся в выборке. |
| `std::unique_ptr<std::weak_ptr<const Book>[]>` | Владеет массивом слабых указателей внутри `Selection`. |
| `const Node*` | Обычный указатель для чтения узла. `.get()` берёт адрес из `unique_ptr`. Владение остаётся у исходного указателя. |

У `unique_ptr` есть `->` для доступа к полям, `*` для получения объекта,
проверка `if (ptr)` на наличие объекта и `.get()` для получения адреса.
`std::make_unique<Node>(book)` создаёт узел и сразу отдаёт его владельцу.

В `book_tree.h` есть `<memory>` и объявление `struct Node;`. Полное определение
узла находится в `book_tree.cpp`. Размещение специальных методов дерева
в этом же файле позволяет компилятору видеть полный тип `Node` там, где
`unique_ptr<Node>` должен уметь его уничтожить.

С обычным `Book*` после удаления книги в старой выборке остался бы прежний
адрес. Проверка `ptr != nullptr` сообщает только, что значение адреса
ненулевое. `weak_ptr::lock()` проверяет срок жизни и возвращает пустой
`shared_ptr`, если объект уничтожен. Успешный `lock()` создаёт ещё одного
сильного владельца. Последний `shared_ptr` освобождает книгу.

## Методы BookTree

| Метод | Что принимает | Что возвращает и делает |
| --- | --- | --- |
| `insert` | `const Book& book` — полную запись | `bool`. `true` при вставке копии книги, `false` при дубликате года. |
| `find` | `const Book& key` — обычно `Book(год)` | `std::weak_ptr<const Book>` на найденную запись. При отсутствии ключа возвращает пустой указатель. |
| `remove` | `const Book& key` — обычно `Book(год)` | `bool`. `true` при удалении, `false` при отсутствии ключа. Успешное удаление уменьшает размер на один. |
| `size` | Без аргументов | `std::size_t`. Возвращает сохранённый `size_`. |
| `height` | Без аргументов | `std::size_t`. Для пустого дерева `0`, для одного узла `1`. |
| `select` | `const Criterion& criterion` | `Selection` с подходящими книгами по возрастанию года. |
| `inOrder` | Без аргументов | `Selection` со всеми книгами по возрастанию года. |
| `reverseOrder` | Без аргументов | `Selection` со всеми книгами по убыванию года. |

```cpp
BookTree tree;
tree.insert(Book("Dune", "Herbert", 1965, 412));

const auto found = tree.find(Book(1965));       // weak_ptr<const Book>
if (const auto book = found.lock()) {          // shared_ptr<const Book>
    std::cout << book->title() << '\n';
}
```

В примере сильный указатель `book` освобождается в конце блока `if`. Сама
`found` может жить дольше узла или всего дерева. Если перенести переменную
с результатом `lock()` наружу, она сможет удерживать книгу и после `remove()`.

### Внутренние функции

| Функция | Аргументы и результат | Что происходит |
| --- | --- | --- |
| `findLink` | `const Book& key` → `std::unique_ptr<Node>&` | Находит поле `root_`, `left` или `right`. Поле либо владеет узлом с нужным ключом, либо пусто и подходит для вставки. |
| `nodeHeight` | `const Node* node` → `std::size_t` | Для `nullptr` возвращает `0`. Для узла возвращает `1 + max(высота слева, высота справа)`. |
| `traverse` | `const Node* node`, `const Criterion* criterion`, `bool reverse`, `Selection& result` → `void` | Обходит поддерево и дописывает ссылки в `result`. `nullptr` вместо критерия означает, что подходят все книги. `reverse` меняет порядок поддеревьев. |

`findLink` полезен отдельно от `find`. При вставке и удалении нужно
**изменить указатель в родителе или корне**. При поиске достаточно пройти
по адресам узлов и вернуть слабую ссылку на запись. Внутри `findLink`
переменная `link` имеет тип `std::unique_ptr<Node>*`.

| Выражение | Что означает |
| --- | --- |
| `link` | Адрес поля-владельца. По смыслу напоминает `Node**` в BST на C. |
| `*link` | Само поле `unique_ptr<Node>`. Может быть пустым. |
| `**link` | Узел, которым владеет это поле. Разыменовываем после проверки `*link`. |

`findLink` возвращает `*link` по ссылке, поэтому в `insert` запись
`auto& link = findLink(book)` позволяет присвоить `link` новый узел прямо
в нужном поле.

### Три случая удаления

1. **Лист.** Поле, в котором лежал узел, остаётся пустым. Локальный владелец
   освобождает старый узел в конце блока.
2. **Один ребёнок.** Ребёнок перемещается в поле старого узла. Переменная
   `removed` удерживает старый узел, пока из него забирают ребёнка.
3. **Два ребёнка.** Преемник — крайний левый узел правого поддерева.
   Его `shared_ptr<Book>` переносится в исходный узел. Затем правый ребёнок
   преемника занимает его прежнее место. Слабые ссылки на книгу-преемника
   продолжают наблюдать тот же объект. Ссылки на старую книгу истекут после
   освобождения её последнего сильного владельца.

Вот случай с одним правым ребёнком. С обычным `Node*` в C++ нужно было бы
самостоятельно освободить старый узел через `delete`. В C при выделении
через `malloc` на этом месте был бы `free`. С `unique_ptr` освобождение
выполняется при выходе из блока.

```cpp
auto removed = std::move(link);   // Забираем владение старым узлом.
link = std::move(removed->right); // Передаём владение ребёнком в поле дерева.
```

Вставка, поиск и удаление идут по одной ветке и занимают `O(h)`, где `h` —
высота дерева. У вырожденного дерева высота может вырасти до числа узлов.
`size()` занимает `O(1)`, `height()` проходит по всем узлам за `O(n)`.

### Специальные методы дерева

- `BookTree()` создаёт пустое дерево.
- `BookTree(BookTree&& other)` создаёт дерево из `other`. Корень и размер
  переходят в новый объект. У источника корень становится пустым, размер
  вручную обнуляется.
- `operator=(BookTree&& other)` делает перенос в уже существующее дерево.
  Прежний корень получателя освобождается. Результат — `BookTree&`, ссылка на
  объект-получатель. Проверка `this != &other` защищает самоприсваивание.
- `BookTree(const BookTree&)` и `operator=(const BookTree&)` запрещены через
  `= delete`. Копирование потребовало бы отдельного дерева с собственными узлами.
- `~BookTree()` уничтожает корневой `unique_ptr`. Освобождение каскадом доходит
  до листьев.

## Критерии и порядок обхода

`Criterion` играет ту же роль, что базовый `Shape` в ЛР4. У него есть
виртуальный деструктор и чисто виртуальный `bool matches(const Book&) const`.
`BookTree` принимает ссылку на критерий, а вызов `matches` выбирает реализацию
конкретного класса.

- `BookSelector(int lo, int hi, int minPages)` хранит три числа и проверяет
  оба условия варианта. Требуется `lo >= 1`, `hi >= lo` и `minPages >= 0`.
  Равные границы дают пустой интервал.
- `AllBooks` принимает любую книгу. Он позволяет проверить тот же `select`
  с другим классом критерия.

`select` передаёт адрес критерия в `traverse`. `inOrder` и `reverseOrder`
передают `nullptr`, так как им нужны все записи. Симметричный обход
«лево, узел, право» уже даёт порядок по возрастанию ключа. При обратном
обходе левое и правое поддеревья меняются местами в порядке посещения.
В каждом узле `select` сразу проверяет критерий и дописывает подходящую
слабую ссылку. Если один вызов `matches` занимает `O(1)`, весь обход требует
`O(n)` времени, `O(h)` стека рекурсии и `O(k)` памяти для `k` найденных позиций.

## Selection и печать

`Selection` похожа на массив из ЛР3. Внутри есть `data_`, `size_` и
`capacity_`. Вместимость растёт как `1, 2, 4, 8…`. При росте старые слабые
указатели копируются в новый буфер, а старый буфер освобождается его
`unique_ptr`. Добавление стоит амортизированно `O(1)`.

| Метод | Аргументы и результат |
| --- | --- |
| `Selection()` | Создаёт пустую выборку без выделения буфера. |
| `size()`, `capacity()` | Возвращают `std::size_t`. Размер считает все позиции, включая истёкшие. Вместимость показывает, сколько позиций помещается в текущий буфер. |
| `empty()` | Возвращает `bool` по условию `size() == 0`. |
| `operator[](std::size_t index)` | Возвращает `const std::weak_ptr<const Book>&`. Доступ за пределами размера бросает `std::out_of_range`. Для чтения книги используй `selected[i].lock()`. |
| `append(std::weak_ptr<const Book> book)` | Дописывает слабую ссылку и при необходимости увеличивает буфер. Тип результата — `void`. |
| `swap(Selection& other)` | Меняет местами буферы, размеры и вместимости. Тип результата — `void`. |
| `Selection(const Selection& other)` | Выделяет свой массив и копирует слабые ссылки. Обе выборки наблюдают за теми же книгами. |
| `Selection(Selection&& other)` | Забирает массив и оставляет источник пустым. |
| `operator=(const Selection& other)` | Сначала создаёт копию, затем обменивается с ней содержимым. Возвращает `Selection&` на получателя. |
| `operator=(Selection&& other)` | Освобождает старый буфер и забирает массив источника. Возвращает `Selection&` на получателя. |
| `~Selection()` | Деструктор по умолчанию. `unique_ptr` сам освобождает массив. |

Например, так можно прочитать первую живую книгу в выборке по варианту.

```cpp
const Selection selected = tree.select(BookSelector(1960, 1990, 250));
for (std::size_t i = 0; i < selected.size(); ++i) {
    if (const auto book = selected[i].lock()) {
        std::cout << book->title() << '\n';
        break;
    }
}
```

Два свободных `operator<<` принимают `std::ostream&` слева и либо
`const Book&`, либо `const Selection&` справа. У метода класса левым
операндом был бы сам объект этого класса. Свободная функция даёт привычную
запись `std::cout << selected`. Оба оператора возвращают тот же поток
по ссылке, поэтому работает цепочка `std::cout << book << '\n'`.

При печати выборки сначала выводится размер, потом для каждого элемента
вызывается `lock()`. Живая книга печатается через оператор для `Book`,
истёкшая ссылка — одной строкой `[expired]`.

## Когда можно писать auto

`auto` выводит тип на этапе компиляции. Если вывелся тот же тип, что в явном
объявлении, поведение и производительность совпадают. Строки с `root_` и
`findLink` ниже относятся к коду внутри `BookTree`.

```cpp
auto node = root_.get();            // Node*
auto* pointer = root_.get();        // Тоже Node*, звёздочка подчёркивает тип.
const auto* readOnly = root_.get(); // const Node*, читать через него можно.

auto book = found.lock();          // std::shared_ptr<const Book>
auto& link = findLink(key);        // std::unique_ptr<Node>&
```

`auto*` подходит для обычного указателя. Для `shared_ptr` пиши `auto`.
В последней строке важен `&`. С `auto&` переменная ссылается на существующее
поле дерева. Запись `auto link = findLink(key)` попыталась бы скопировать
`unique_ptr` и не скомпилировалась бы.

## Как устроены тесты

В [tests.cpp](tests.cpp) есть 29 сценариев Google Test. `TEST(Группа, Имя)`
объявляет один сценарий. Действия внутри мы пишем сами. Например,
`BookTree.rejects_duplicate_year` вставляет две книги одного года и проверяет
возвращаемый `bool`, размер дерева и содержимое первой записи.

| Заголовок | Где он нужен |
| --- | --- |
| `<initializer_list>` | `expectYears` принимает ожидаемые годы в фигурных скобках, например `{1951, 1961, 1965}`. |
| `<sstream>` | `std::ostringstream` собирает вывод в строку. Тест вызывает `out << selected` и сравнивает `out.str()` с ожидаемым текстом. |
| `<type_traits>` | Даёт вопросы о свойствах типов. Например, `std::is_abstract_v<Criterion>` даёт `true` для абстрактного класса. |

`EXPECT_*` фиксирует ошибку и продолжает проверки. `ASSERT_*` при ошибке
прерывает текущую функцию. В `expectYears` сначала проверяется размер,
затем успешность `lock()`, и только потом читается год. Если нужно прервать
сам тест при фатальной ошибке внутри вспомогательной функции, здесь
используется `ASSERT_NO_FATAL_FAILURE(expectYears(...))`.

Четыре `static_assert` в начале файла срабатывают при компиляции цели `tests`.
Они проверяют запрет копирующего конструктора и присваивания дерева,
абстрактность `Criterion` и наличие у него виртуального деструктора.
Эти строки работают со свойствами типов без создания объектов. Условие
требует соответствующих свойств классов и минимум 14 тестов Google Test.
Проверять свойства через `static_assert` — выбор этой реализации.

Для разбора владения достаточно сначала прочитать три теста.

1. `BookTree.removes_root_with_two_children` проверяет порядок после удаления
   и сохранение объекта книги-преемника.
2. `Selection.copy_has_own_array_and_both_refs_expire` проверяет два независимых
   массива и истечение одной и той же ссылки в обоих.
3. `Lifetime.lock_keeps_book_alive_until_released` сохраняет результат
   `lock()` и проверяет момент, когда книга действительно уничтожается.
   Соседний тест `Lifetime.removal_and_destruction_release_records` проверяет
   счётчик после удаления и уничтожения дерева.

## CMake, запуск и VS Code

Проект использует CMake 3.20+ и C++20. В [CMakeLists.txt](CMakeLists.txt) две цели.
`main` собирает демонстрацию,
`tests` — тесты. Обе получают `book.cpp` и `book_tree.cpp`. `FetchContent`
подключает Google Test, `GTest::gtest_main` даёт готовый `main` для тестов,
а `gtest_discover_tests` регистрирует отдельные тесты в CTest.

Из корня репозитория настройка, сборка, прогон и демонстрация выглядят так.

```powershell
cmake -S lab5 -B lab5/build
cmake --build lab5/build
ctest --test-dir lab5/build --output-on-failure
.\lab5\build\main.exe
```

Для выборочного прогона можно добавить `-R`. Например, следующая команда
запускает группу `Lifetime`.

```powershell
ctest --test-dir lab5/build -R '^Lifetime\.' --output-on-failure
```

Если редактор подчёркивает `std::strong_ordering` и операторы сравнения,
проверь, что IntelliSense использует тот же компилятор и C++20, что и сборка.
Локальные настройки VS Code в корне репозитория указывают ЛР5 и её
`compile_commands.json`. Для существующей Ninja-сборки базу команд можно
обновить так.

```powershell
cmake -S lab5 -B lab5/build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

В обычной сборке проверяются предупреждения. Для ASan используется флаг
`-DENABLE_ASAN=ON`. На установленном MinGW проверка с ASan останавливалась
на `cannot find -lasan`. Команды для обязательного прогона ASan/LSan на Linux
есть в [инструкции по сборке](README.md#сборка).
